### Plot editability (without code)
The key design decision: plots are hardcoded in constants for structural/agronomic data, but user-facing labels and color themes are stored in `db.plotLabels` and `db.plotThemes` (JSONB in Supabase). The **Edit** tab in PlotSidePanel lets the user:
- Rename any plot (e.g., "Pepperoncini" → "Provider Beans")
- Change its color theme (8 options: Tomato, Pepper, Cucumber, Carrot, Lettuce, Corn, General, Neutral)
- Reset to default
This satisfies the "replaced a pepper with a bean" use case and supports next-season replanning without touching code.

## Key decisions made this session

- **No separate auth for Sow** — Lattice Supabase auth is the only gate; no PIN, no new login
- **Fresh start on data** — old localStorage data not migrated; user accepted this
- **JSONB blob model** — one row per lattice in `garden_data`, full state as JSONB; consistent with original garden agent's data model
- **Full client component** — `/sow` is a `'use client'` SPA with all tabs and state; no server components inside
- **Inline styles throughout** — avoids any Tailwind config dependency for Sow; consistent with the original garden agent's approach
- **Plot structure is constants, plot customization is DB** — right split between fixed agronomic data and user-editable config
